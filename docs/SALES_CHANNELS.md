# Sales Channels

Quantum Terminal Pro Dashboard should be sold as a professional control layer for
existing trading bots, not as a profit-guaranteeing bot.

| Layer | Tool | Purpose |

## First 30-Day Sales Plan

Week 1:

- Make GitHub public.
- Add screenshots or a short screen recording.
- Publish the Early Access checkout page.
- Pin one X/Twitter post with the product promise and GitHub link.

Week 2:

- Post daily short clips: Trade Manager, Diagnostics, Manual Actions, Adapter
  Contract, AWS Install.
- DM Python bot developers and small algo traders.
- Offer three discounted setup slots to get testimonials.

Week 3:

- Publish one technical article: "How to add a manual intervention layer to a
  trading bot."
- Share the adapter contract in communities without spamming the paid offer.
- Collect objections and improve the install guide.

Week 4:

- Move the default price from Early Access to Pro if there is traction.
- Keep Setup Included available for buyers who do not want to touch Linux.
- Start quoting Custom Adapter as a service, not a cheap add-on.

## Content Angles

- "Your bot can trade, but can you safely control it?"
- "A trading bot without a risk console is hard to operate."
- "Adapter-first dashboard: connect any bot that writes JSON state files."
- "Manual actions should be queued, validated, and logged, not fired blindly."
- "Self-hosted dashboard for Binance, OKX, Bybit, Alpaca, and custom bots."

## Avoid

- Do not promise profit.
- Do not advertise win rate or bot performance as the dashboard's value.
- Do not imply that manual buttons bypass exchange risk.
- Do not position it as a beginner trading system.
